Theory

How parity catches a flipped bit

Everything you need to reason about parity bits — the mechanism, the math, and where it actually gets used.

What is a parity bit?

A parity bit is one extra bit added to a group of binary data. Its only job is to make the total count of 1s in the frame follow a fixed rule — either always even or always odd. If a single bit flips during transmission, that rule breaks, and the receiver knows something went wrong.

Even Parity

The parity bit is chosen so the total number of 1s (data bits + parity bit) is even. If the data already has an even number of 1s, the parity bit is 0. If it has an odd number, the parity bit is 1.

1011001 → four 1s (even) → parity = 0 → send 10110010

Odd Parity

The parity bit is chosen so the total number of 1s is odd. If the data has an even count, the parity bit becomes 1 to make it odd; if the data is already odd, the parity bit is 0.

1011001 → four 1s (even) → parity = 1 → send 10110011

Advantages

  • Extremely simple and cheap to implement in hardware.
  • Adds only one extra bit of overhead per frame.
  • Fast to compute — a single XOR chain.
  • Reliably catches any single-bit error.

Disadvantages

  • Cannot detect an even number of flipped bits (2, 4…).
  • Cannot correct errors — only detects that one occurred.
  • Doesn't identify which bit is wrong.
  • Weak against burst errors compared to CRC or checksums.

Applications

  • RAM error checking (parity/ECC memory modules).
  • Serial communication (RS-232, UART framing).
  • Older storage and bus protocols (SCSI, PCI).
  • Simple network link-layer checks and embedded systems.

Real-life example

Think of a courier who must deliver an even number of boxes. If the warehouse count is odd, they add one empty "filler" box so the receiving dock — which only checks "even or odd" — can instantly tell if a box went missing in transit, without inspecting every single one.
